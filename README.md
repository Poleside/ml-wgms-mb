# ML4GM mass balance

Code for *Reconstructing annual and seasonal glacier mass balance across the global observational network, 1979–2025* (manuscript v0.3.30). The workflow combines WGMS observations, RGI 6.0 glacier attributes and ERA5-Land climate forcing to train and evaluate XGBoost models, fill gaps in annual and seasonal records, quantify uncertainty and reproduce the paper's figures.

## Setup

```sh
conda env create -f environment.yml
conda activate ml4gm-tc
```

## Inputs

Obtain these inputs from the original providers. Paths are relative to the working directory, which defaults to the repository root.

| Source | Version and input files |
| --- | --- |
| WGMS Fluctuations of Glaciers | [2026-02-10 release](https://doi.org/10.5904/wgms-fog-2026-02-10). Put `glacier.csv` and `mass_balance.csv` in `data/DOI-WGMS-FoG-2026-02-10/data/`. |
| Randolph Glacier Inventory | [RGI 6.0, NSIDC-0770](https://doi.org/10.7265/4M1F-GD79). Put all 19 regional attribute CSVs (`01_rgi60_*.csv` through `19_rgi60_*.csv`) in `data/RGI6/`. For Fig. 2, add `00_rgi60_O1Regions.shp` and its shapefile sidecar files there. |
| ERA5-Land | Use the [Earth Engine Monthly Aggregated collection](https://developers.google.com/earth-engine/datasets/catalog/ECMWF_ERA5_LAND_MONTHLY_AGGR), `ECMWF/ERA5_LAND/MONTHLY_AGGR`, and the export steps below. See the [ERA5-Land reference article](https://doi.org/10.5194/essd-13-4349-2021) and the collection's terms of use. |
| Natural Earth | Cartopy can fetch the 1:110 million [physical](https://www.naturalearthdata.com/downloads/110m-physical-vectors/) and [cultural](https://www.naturalearthdata.com/downloads/110m-cultural-vectors/) layers on first use. For offline use, place the standard `ne_110m_*` shapefiles and their sidecars in the respective `physical/` or `cultural/` directory under `figures/cartopy_data/shapefiles/natural_earth/`. |

### Export monthly climate forcing

1. Run `python run_notebooks.py 01`. On the first run without climate data, the notebook stops after writing `data/raw/era5land_gee/wgms_global_glacier_points_for_gee.csv`.
2. Upload that table as an asset in your Earth Engine project. In the Earth Engine Code Editor, open [the export script](code/gee_export_era5land.js), set `POINT_ASSET` to your table asset, and start the CSV export for 1979–2025. If exporting in batches, use nonoverlapping year ranges or regions that together cover the study inputs.
3. Place downloaded shards in `data/raw/era5land_gee/exports/` and rerun step 01. Alternatively, put the normalized monthly table at `data/raw/era5land_gee/wgms_global_era5land_1979_2025.csv` before running step 01.

Use the 1979–2025 export to match the manuscript. Some early 1979 seasonal windows are truncated at the start of the forcing record; aggregation uses the available months. For a separate sensitivity run, place a 1978 export from the same collection and centroid asset in `data/raw/era5land_gee/extension/`, rerun from step 01 and repeat hyperparameter selection.

## Run the analysis

After step 01 completes, run:

```sh
python run_notebooks.py 02 03 04 05 06 08 09
python code/14_regional_change_attribution.py
```

The runner executes notebooks in separate processes without modifying them. With all inputs in place, `python run_notebooks.py all` runs steps 01–09; step 14 runs separately. Pass `--root` to the runner, attribution script and plotting commands to use the same existing external working directory.

| Step | Output |
| --- | --- |
| 01–02 | Linked inputs, seasonal windows and model-ready training matrices |
| 03–04 | Hyperparameter search, trained models, held-out predictions, metrics and window validation |
| 05–06 | Annual and seasonal reconstructions, observation/model flags and uncertainty |
| 08–09 | Benchmark comparisons and predictor diagnostics |
| 14 | Regional changes and signed predictor-group contributions for Fig. 9 |

The workflow writes generated files under `data/`, `models/` and `results/`. Training matrices, search logs and fitted models are generated by the code. To recompute search results after changing the training inputs, set `ML4GM_FORCE_PARAM_SEARCH=1` in the environment before running step 03. Initial training includes a 144-combination search per target, 10-fold random cross-validation, leave-one-glacier-out and leave-one-year-out evaluations.

## Generate the figures

For Fig. 1, install Arial and Node.js 20.9 or later, then run `npm install` from the repository root. This installs the pinned Sharp renderer listed in `package.json`. The remaining figures use the Python environment.

```sh
python figures/make_figures.py --dpi 300
```

Figures and source tables are written to `figures/exports/`. Use `--figure N` to render an individual figure. Use `--figure 2 --dpi 600` for the manuscript map's original raster dimensions; the submitted PNG stores those pixels with 300 dpi metadata. Run `python figures/check_figure09_results.py` to check the regional sample counts and signed contributions against the manuscript.

Sanity checks for v0.3.30: the annual, winter and summer training sets contain 5,465, 2,519 and 2,488 records. The cumulative annual balance in Fig. 7 rounds to −9.04 m w.e. for the study sample and −15.40 m w.e. after regional area reweighting. Figures 5 and 7 show ± one empirical standard uncertainty.
